## Context

参见 [proposal.md](./proposal.md) 的动机和能力范围。当前仓库只有 OpenSpec 文档，没有既有应用代码或数据需要迁移。首版面向 macOS 13 及以上，作为普通本机应用开发和测试；Mac App Store 发布不是当前交付条件。当前机器可运行 Swift 6.2，且命令行工具可导入 SwiftUI、AppKit 和 SQLite3；先用 Swift Package Manager 构建可执行程序，再打包为本机试用的 `.app`。正式签名和商店发布时再配置完整 Xcode。

## Goals / Non-Goals

**Goals:**

- 用独立的剪贴板监听、历史存储、快捷入口和粘贴模块隔离系统 API 与界面，便于测试和替换实现。
- 首版完整支持纯文本、URL 和位图：记录、预览、搜索可搜索内容、再次复制；图片可预览并再次复制。
- 保持离线运行，明确记录状态与本地数据位置，让暂停、排除应用、保留期限和清空操作有可预测的结果。
- 在没有辅助功能授权或自动粘贴失败时，仍能完成“复制历史项，用户自行粘贴”的核心流程。

**Non-Goals:**

- 首版不做账户、云同步、OCR、跨设备同步、剪贴板内容分析或插件系统。
- 首版不保存文件对象，也不承诺还原 HTML、RTF 等富文本格式；这类内容可按其纯文本表示记录。
- 不将 App Store 审核、沙盒或自动更新作为当前版本的发布门槛。

## Decisions

### 1. 原生应用外壳与界面

使用 Swift Package Manager 管理源代码和测试，打包脚本生成本机试用的 `.app`。SwiftUI 编写历史列表、搜索和设置；AppKit 的 `NSStatusItem` 提供菜单栏入口，`NSPanel` 承载可由全局快捷键呼出的快速面板，SwiftUI 视图通过 `NSHostingView` 嵌入。快速面板在键盘导航、焦点和主动显示位置上需要比普通菜单栏弹窗更细的控制，因此选择这一组合；单用 `MenuBarExtra` 实现更简单，但这类交互的可控性较弱。界面状态只调用服务接口，不直接读写 `NSPasteboard` 或数据库。

模块边界：`ClipboardMonitor` 负责检测变化并解析内容；`HistoryStore` 负责持久化、去重、查询和清理；`HotkeyService` 负责注册快捷键；`QuickPasteController` 负责将历史项写回剪贴板并按需粘贴；`SettingsStore` 负责记录策略。模块通过 `ClipItem`、`CapturePolicy` 等小型数据类型通信。

### 2. 剪贴板监听与内容归一化

监听 `NSPasteboard.general.changeCount`，应用启动时只记下当前计数，不追溯启动前的内容。运行中以约 500 毫秒间隔检查；计数变化后读取当前剪贴板，优先识别 URL、图片、纯文本，并将可处理的内容交给 `HistoryStore`。系统没有为这个场景提供需要依赖的跨应用剪贴板变更事件，因此采用定时检查；相比持续扫描内容，只在计数变化时解析，降低资源消耗。

写回历史项时记录本应用产生的 `changeCount`，避免再次捕获自己写入的内容。对连续多次复制的相同类型、相同规范化内容计算 SHA-256，更新该项的最近复制时间并移到列表前面，而不增加重复记录。空内容、无法解析的类型以及超过 20 MiB 的单项直接跳过，并在本地记录不含内容正文的诊断信息。对于同时含多种表示的剪贴板项，先选一个主要表示；富文本的纯文本回退会失去格式。

### 3. 本地存储与查询

使用系统 SQLite3，在应用的 Application Support 目录维护 `clips` 表：`id`、`kind`、`text`、`sourceBundleID`、`contentHash`、`createdAt`、`lastCopiedAt`、`copyCount`、`isPinned`、`payloadPath`。图片原始数据放在同目录的受控子目录，数据库只存相对路径；图片文件先原子写入，再提交记录，删除记录时同步清理文件。界面按需加载图片预览并限制内存缓存数量。设置用 `UserDefaults` 保存，不把内容写入日志或遥测。

首版最多保留 1000 条未固定记录，默认保留 30 天；固定项不自动清理，用户可逐项删除。由于列表有上限，查询先按固定状态和最近使用时间加载元数据，文本与 URL 用 Swift 的本地化不区分大小写包含匹配；无需先引入全文索引。SQLite 比单个 JSON 文件更适合频繁插入、按时间排序和后续数据迁移；图片也不适合塞进 `UserDefaults`。

### 4. 快捷入口与再次使用

全局快捷键通过系统 `RegisterEventHotKey` 注册，并提供自定义组合及冲突提示；注册失败时菜单栏入口仍可用。选择历史项后，`QuickPasteController` 将相应表示写回系统剪贴板。“复制”是始终可用的操作。

“自动粘贴”是用户主动触发的可选操作：打开面板时记住原前台应用，选中后关闭面板、激活该应用，再尝试发送粘贴按键。只在用户启用该功能并获得所需辅助功能授权后执行；目标应用不可用、授权缺失或发送失败时停在“已复制”状态并给出清楚提示。该模块不读取目标应用的内容，也不注入后台常驻进程。

### 5. 隐私与记录策略

首次启动先展示本地保存行为和设置入口，由用户明确启用记录。`ClipboardMonitor` 在读取内容前检查暂停状态和排除应用的 Bundle ID；前台应用由 `NSWorkspace` 获取。暂停后不新增记录，恢复时重新设定 `changeCount` 基线，避免补录暂停期间的内容。清空历史同时删除数据库记录和图片文件；排除设置只影响之后的复制。

不把剪贴板内容上传网络，不集成分析 SDK。数据库与图片使用应用支持目录及仅当前用户可读写的文件权限。首版不增加应用层加密：文件仍受本机账户与磁盘安全配置保护，因此设置页应说明本地历史的敏感性，并提供快速暂停与清除能力。

## Risks / Trade-offs

- **轮询可能漏掉极短时间内被连续覆盖的内容** → 在真实使用场景测试 500 毫秒间隔和资源占用；只承诺捕获检查时仍存在的最新内容。
- **前台应用可能在复制后、下一次检查前切换** → 应用排除按检查时观察到的前台应用尽力判断；界面说明这一限制，不能将其宣传为绝对的密码保护。
- **剪贴板可能包含密码或其他敏感信息** → 首次启用提示、暂停与应用排除、30 天默认保留、清空入口和不记录正文日志；不自动上传。
- **自动粘贴依赖系统授权、目标应用焦点和目标应用行为** → 将其与核心复制流程隔离；所有失败路径保留已复制内容，并用真实应用手工验证。
- **图片历史可能占用较多磁盘** → 限制单项大小、未固定项数量和保留时间；预览按需加载并限制内存缓存，清理时删除对应文件。
- **本机历史没有应用层加密** → 权限最小化并明确告知；若后续需要强保护，再单独设计密钥管理和数据迁移。

## Migration Plan

1. 创建 Swift Package Manager 应用和测试目标，确定 Bundle ID、Application Support 数据目录与本机 `.app` 打包脚本。
2. 先实现 `ClipItem`、内容归一化和 SQLite 存储，再接入监听；用单元测试验证去重、清理和搜索，用集成测试验证剪贴板读写与重启后的持久化。
3. 实现菜单栏、快速面板、快捷键和设置；用真实编辑器、浏览器及图片复制场景验证焦点、权限拒绝和自动粘贴回退。
4. 为数据库加入 `schema_version` 和增量迁移入口。当前没有旧版本数据；将来升级先迁移再启动监听，迁移失败则保留原文件、停止记录并提示用户，避免覆盖历史。
5. 先交付本机可运行的 `.app` 供试用。若后续决定上架 Mac App Store，再针对沙盒、签名、隐私资料与自动粘贴能力做单独验证和发布设计。
