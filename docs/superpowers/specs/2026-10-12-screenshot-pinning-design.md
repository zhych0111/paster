# Paster 截图与桌面贴图设计

日期：2026-10-12

状态：设计初稿，待产品体验与真机验证

## 目标与首版范围

在现有 Paster 菜单栏应用中增加“区域截图并贴在屏幕上”。用户从菜单或独立快捷键启动系统区域选择，松开鼠标后立即得到一张始终位于普通窗口前方的图片；可以移动、等比缩放、复制、另存为 PNG 或关闭。多张贴图可以同时存在，退出 Paster 后全部关闭。截图功能与剪贴板记录开关独立；Paster 不自动复制截图，只有用户在贴图上选择“复制”时才由应用写入系统剪贴板。系统交互式截图本身有按住 Control 将结果送入剪贴板的行为，该操作仍可能触发已启用的剪贴板历史。

首版不做标注、OCR、滚动截图、窗口截图、截图历史、贴图跨重启恢复或云同步；不改应用名、Bundle ID 和现有剪贴板数据库。现有最低版本 macOS 13 保持不变。“置顶”定义为位于普通应用窗口之上；全屏应用、Mission Control、Stage Manager 和多个 Space 的行为需要单独验收，不承诺跨所有空间永久显示。

## 方案选择

| 方案 | 优点 | 代价 | 决定 |
| --- | --- | --- | --- |
| 调用系统 `screencapture -i -s`，Paster 管理贴图窗口 | 区域选择与多显示器交互交给系统；实现范围小，适合当前 macOS 13 目标 | 依赖系统命令；权限归属、取消状态和未来沙盒发布要真机验证 | **首版采用** |
| ScreenCaptureKit + 自绘选择层 | 截图流程完全由应用控制，适合后续标注与预览 | 需要自己处理选择、屏幕坐标、显示器缩放、排除自身窗口和 macOS 13 的 API 兼容 | 后续按需迁移 |
| 单独开发截图 App | 发行与权限隔离 | 重复菜单栏、快捷键、安装和图片处理；两个 App 的联动复杂 | 当前不采用 |

截图入口只通过 `ScreenshotCaptureService` 暴露 `captureRegion()`；贴图模块不依赖具体截图方式，便于以后替换为 ScreenCaptureKit。系统命令必须以 `Process` 的参数数组调用，不经过 shell 拼接。

## 交互流程

1. 菜单栏增加“区域截图并贴图”；设置里增加独立快捷键，默认建议 `⌥⇧S`，避免把 Control 保持到系统选区阶段。注册失败时提示冲突，菜单入口仍可用；不能覆盖现有的 `⌃⌥V` 剪贴板快捷键。现有 `HotkeyService` 固定注册 V 键与单个 ID，需定向改为统一注册表、为两个动作分配不同 ID，并在 Carbon 回调中按事件 ID 路由；两项快捷键分别保存设置和冲突状态。
2. 启动截图前记住历史面板和每张贴图的可见状态，再暂时隐藏这些窗口，避免截进新图；结束后按原状态恢复。用户按 `Esc` 取消时不创建图片，也不弹错误；其他无截图结果的情况不能直接当作取消。
3. 成功截图后在鼠标附近显示贴图，初始尺寸按截图纵横比缩放到所在屏幕可见区域内；原始图片分辨率不因窗口缩小而丢失。
4. 拖动图片移动窗口；拖动边角等比缩放，设置最小可操作尺寸。悬停时显示关闭、复制、另存为按钮；右键菜单提供相同操作。复制后显示简短反馈，另存为由用户选择路径。
5. 每张贴图独立关闭。退出应用时销毁所有贴图和内存图片。首版贴图只存在于当前运行会话，不自动写入磁盘或剪贴板历史。历史面板和贴图处于相同浮动级别，按用户最近激活的窗口决定前后；新截图先恢复原有面板，再将新贴图置前。

## 组件与数据流

- `ScreenshotCaptureService`：启动 `/usr/sbin/screencapture` 的交互式区域选择，以 `-i -s -x -t png` 和唯一的私有临时文件路径接收结果。异步接收进程结束事件，不在主线程调用阻塞式等待；结合退出码、标准错误、文件存在性、截图前后的剪贴板变化及真机确认过的行为区分成功、`Esc` 取消、Control 转存剪贴板和失败。Control 转存时不从剪贴板自动生成贴图，提示“截图已复制到剪贴板；要贴图请重试并松开 Control”；无法确认的无文件结果按失败处理。成功时检查 PNG 可解码性，将图片交给贴图管理器。服务持有子进程引用，正常退出应用时先取消截屏、终止子进程，等它结束后清理临时文件；异常退出遗留文件在下次启动时清理。
- `PinnedImageManager`：在主线程持有各贴图窗口及原始图片，负责创建、关闭、隐藏/恢复和资源释放。首版最多 10 张、单张最多 2500 万像素、全部贴图合计最多 5000 万像素（按 RGBA 估算约 200 MiB）；单张超限提示缩小选区，张数或合计像素超限提示关闭贴图，不静默丢弃旧图或载入过大的图片。
- `PinnedImageWindow`：AppKit 的独立无边框窗口，使用浮动级别、阴影和等比缩放；图片与悬停工具栏由视图承载。窗口关闭时释放图片引用。默认跟随创建时的当前 Space，不主动设置“所有 Space 显示”。
- `ScreenshotCommandController`：接入现有菜单栏和快捷键服务，串联隐藏贴图、截图、恢复贴图和创建新窗口；避免重复触发造成并发截图。截图进行时不停止剪贴板监听，也不改写现有录制设置。

图片在内存中传递。贴图上的“复制”操作将图片写入 `NSPasteboard`；它应复用现有的本应用写入标记，防止监听器误把 Paster 的写入当作外部复制。用户在系统截图交互中按住 Control 也可能直接写入剪贴板，这属于系统行为，已启用的历史监听可能记录该结果；需要在帮助文字中提示并真机验证。若 Control 转存的退出状态与剪贴板变化在目标系统上无法可靠识别，统一按“未生成贴图，可重新截图”提示，不读取可能来自其他应用的剪贴板图片。首版不额外把贴图图片写入历史；如果未来要支持“截图自动进历史”，应作为单独设置设计，并严格遵守记录开关、排除应用和保留策略。

## 权限、隐私与失败处理

首次启动 Paster 不请求截屏权限；只有用户主动截图时才进入系统截屏流程。macOS 可能要求“屏幕与系统音频录制”一类授权；界面需说明授权用途，并在失败时给出系统设置入口。因为系统命令的授权归属可能随系统版本和打包方式变化，开发阶段必须在干净用户账户、实际 `.app` 和 DMG 安装版上验证；若出现不可解释的归属或重复授权，改用原生 ScreenCaptureKit 实现，不把该问题留给用户。

截图临时目录只允许当前用户访问；成功解码后立即删除临时 PNG。贴图默认不持久化、不上传、不写入日志；错误日志只记录错误类别和状态，不含图片路径或像素。另存为必须由用户明确选择。拒绝授权、命令启动失败、图片损坏和磁盘写入失败均保持现有贴图不变，并给出可操作提示。

## 验收与风险

- 手工验证 macOS 13 及当前开发机系统上的截图成功、`Esc` 取消、拒绝/授予权限；分别覆盖 Retina、外接屏、不同缩放比例和跨屏拖动。先从新构建的 `.app` 重制含此功能的 DMG，再验收该 DMG 的首次安装与截图；现有 v0.1.0 DMG 只是旧版快照，不能用于此项验收。
- 验证多张贴图置顶、移动、等比缩放、关闭、复制、另存为，以及切换 Space、Mission Control、全屏应用和 Stage Manager 时的实际行为；把系统限制写入帮助文字。
- 验证截图前隐藏的旧贴图和历史面板在成功、取消和异常三个分支都按原状态恢复；验证系统截图按住 Control 时的剪贴板行为，以及建议的 `⌥⇧S` 快捷键进入选择的场景。正常退出期间若仍在选区，AppKit 终止流程需延后直到子进程结束与临时文件清理完成；强制退出遗留文件在下次启动清理。原有剪贴板监听、历史搜索和快捷键仍正常。
- 为截图服务和贴图管理器设计可替换接口，用模拟捕获结果测试状态流转、并发防护、上限和清理；窗口层与系统授权必须在真实 macOS 图形会话中验收。现有命令行自测不能证明真实窗口置顶或授权行为。

## 技术依据

- 本机 `man screencapture`：`-i` 交互选择、`-s` 限制为区域选择、`Esc` 取消、`-t` 指定格式。
- [Apple ScreenCaptureKit 文档](https://developer.apple.com/documentation/screencapturekit)：原生捕获的后续替换方向及权限要求。
- [Apple NSWindow.Level 文档](https://developer.apple.com/documentation/appkit/nswindow/level-swift.property)：浮动窗口位于普通级别窗口之前。
- [Apple NSWindow.CollectionBehavior 文档](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct)：Space、全屏和 Stage Manager 的窗口行为选项。
