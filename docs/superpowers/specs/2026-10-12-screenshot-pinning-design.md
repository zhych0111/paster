# Paster 截图与桌面贴图设计

日期：2026-10-12

状态：设计初稿，待产品体验与真机验证

## 目标与首版范围

在现有 Paster 菜单栏应用中增加区域截图、纵向滚动截图和桌面贴图。区域截图后直接生成贴图；滚动截图先预览拼接结果，再由用户选择贴图、复制或保存。贴图位于普通窗口前方，可移动、等比缩放、复制、另存为 PNG 或关闭。多张贴图可以同时存在，退出 Paster 后全部关闭。截图功能与剪贴板记录开关独立；Paster 不自动复制截图，只有用户在贴图或滚动截图预览中选择“复制”时才由应用写入系统剪贴板。系统交互式区域截图本身有按住 Control 将结果送入剪贴板的行为，该操作仍可能触发已启用的剪贴板历史。

滚动截图以“尽量支持所有可滚动应用”为目标，覆盖浏览器、PDF 阅读器、文档和常见原生或跨平台滚动视图；不承诺所有应用都能自动滚动或无缝拼接。首版不做横向滚动、标注、OCR、窗口截图、截图历史、贴图跨重启恢复或云同步；不改应用名、Bundle ID 和现有剪贴板数据库。现有最低版本 macOS 13 保持不变。“置顶”定义为位于普通应用窗口之上；全屏应用、Mission Control、Stage Manager 和多个 Space 的行为需要单独验收，不承诺跨所有空间永久显示。

## 方案选择

| 方案 | 优点 | 代价 | 决定 |
| --- | --- | --- | --- |
| 调用系统 `screencapture -i -s`，Paster 管理贴图窗口 | 区域选择与多显示器交互交给系统；实现范围小，适合当前 macOS 13 目标 | 依赖系统命令；权限归属、取消状态和未来沙盒发布要真机验证 | **首版采用** |
| ScreenCaptureKit + 自绘选择层 | 截图流程完全由应用控制，适合连续采样、标注与预览 | 需要自己处理选择、屏幕坐标、显示器缩放、排除自身窗口和 macOS 13 的 API 兼容 | 滚动截图首版采用；普通区域截图后续按需迁移 |
| 单独开发截图 App | 发行与权限隔离 | 重复菜单栏、快捷键、安装和图片处理；两个 App 的联动复杂 | 当前不采用 |

区域截图继续通过 `ScreenshotCaptureService.captureRegion()` 调用系统交互界面。滚动截图另用自绘选区和 ScreenCaptureKit 的 `SCStream` 捕获固定区域的连续画面：系统交互截图不返回可复用的选区坐标，无法直接作为滚动截图的采样区域。两种结果都交给同一个贴图模块；以后可把普通区域截图也迁移到 ScreenCaptureKit。系统命令必须以 `Process` 的参数数组调用，不经过 shell 拼接。

## 快捷键参考

本机 iShot Pro 的当前偏好设置中，区域截图为 `⌃B`，从剪贴板贴图为 `⌥S`，显示或隐藏全部贴图为 `⌥H`。其 [App Store 说明](https://apps.apple.com/cn/app/id1611347086)曾提到区域截图默认 `⌥A`；本设计优先参考本机已使用的键位，而不是把产品默认值当作用户习惯。首版用 `⌃B` 启动普通区域截图；滚动截图先提供菜单入口，不预占新的全局快捷键。`⌥S` 对应的剪贴板贴图和 `⌥H` 对应的全部贴图显隐属于后续功能，不占用这两个键位。

## 交互流程

1. 菜单栏增加“区域截图并贴图”；设置里增加独立快捷键，默认 `⌃B`，并允许用户改键。按下快捷键后，等待触发键及其修饰键松开，再启动系统选区，避免默认组合的 Control 被系统解释为“截图到剪贴板”；等待过程不能阻塞主线程。注册失败时提示冲突，菜单入口仍可用；不能覆盖现有的 `⌃⌥V` 剪贴板快捷键。现有 `HotkeyService` 固定注册 V 键与单个 ID，需定向改为统一注册表、为两个动作分配不同 ID，并在 Carbon 回调中按事件 ID 路由；两项快捷键分别保存设置和冲突状态。
2. 启动截图前记住历史面板和每张贴图的可见状态，再暂时隐藏这些窗口，避免截进新图；结束后按原状态恢复。用户按 `Esc` 取消时不创建图片，也不弹错误；其他无截图结果的情况不能直接当作取消。
3. 成功截图后在鼠标附近显示贴图，初始尺寸按截图纵横比缩放到所在屏幕可见区域内；原始图片分辨率不因窗口缩小而丢失。
4. 拖动图片移动窗口；拖动边角等比缩放，设置最小可操作尺寸。悬停时显示关闭、复制、另存为按钮；右键菜单提供相同操作。复制后显示简短反馈，另存为由用户选择路径。
5. 每张贴图独立关闭。退出应用时销毁所有贴图和内存图片。首版贴图只存在于当前运行会话，不自动写入磁盘或剪贴板历史。历史面板和贴图处于相同浮动级别，按用户最近激活的窗口决定前后；新截图先恢复原有面板，再将新贴图置前。

### 滚动截图流程

1. 菜单栏提供“滚动截图”。应用在目标屏幕上显示短暂的选区层，用户框出需要滚动的内容视口；选择区域必须位于同一显示器内。选区层提供“开始”和取消操作。记住目标应用、显示器和选区坐标，然后隐藏 Paster 窗口与选区层，把焦点还给目标应用。采样时 Paster 的进度面板必须位于选区外，且捕获内容过滤器排除 Paster 窗口；没有合适的面板位置时只使用菜单栏进度入口。
2. 默认自动滚动：在选区内部一次只发送一个小步纵向滚动事件，等待画面稳定并完成本步拼接后才发送下一次。会话期间观察目标应用收到的滚轮/触控板滚动、鼠标按下或拖动、键盘按键；一旦检测到不是 Paster 本次会话发出的、可能用于手动滚动的输入，立即取消后续自动滚动并切换到手动模式，当前用户事件仍正常送达目标应用。这个切换在本次截图中保持有效，不会因用户暂时停手而自动恢复；手动模式继续捕获用户滚动后的稳定画面。菜单栏中的截图进度入口和轻量进度面板提供“停止并预览”，不承诺在目标应用聚焦时用 `Esc` 全局停止。事件发送授权不足、目标应用忽略自动滚动、无法可靠监听用户输入时，直接进入手动模式。
3. 比较相邻画面的重叠内容，排除静止的工具栏或悬浮控件，只追加新出现的内容。已经确认发生过滚动后，连续两次没有有效位移才判断到达底部；一开始就不移动时提示用户尝试手动滚动或结束。若重叠不足、画面快速变化或目标窗口改变，停止并显示原因，不静默输出错位长图。
4. 完成或主动停止后显示拼接预览；用户可贴图、复制、保存 PNG 或放弃。中途失败时，如已有可靠片段，可选择预览并保存这段内容。达到单图 2500 万像素、60 次采样或 120 秒任一上限时停止并提示“已达到本次截图上限”，可预览已截部分。长图贴图默认按窗口宽度显示，图片在贴图窗口内部纵向滚动，避免把整张长图缩成看不清的细条。

## 组件与数据流

- `ScreenshotCaptureService`：启动 `/usr/sbin/screencapture` 的交互式区域选择，以 `-i -s -x -t png` 和唯一的私有临时文件路径接收结果。异步接收进程结束事件，不在主线程调用阻塞式等待；结合退出码、标准错误、文件存在性、截图前后的剪贴板变化及真机确认过的行为区分成功、`Esc` 取消、Control 转存剪贴板和失败。Control 转存时不从剪贴板自动生成贴图，提示“截图已复制到剪贴板；要贴图请重试并松开 Control”；无法确认的无文件结果按失败处理。成功时检查 PNG 可解码性，将图片交给贴图管理器。服务持有子进程引用，正常退出应用时先取消截屏、终止子进程，等它结束后清理临时文件；异常退出遗留文件在下次启动时清理。
- `ScrollSelectionOverlay`：仅在选择滚动区域时出现，记录单显示器内的逻辑坐标、目标应用和滚动事件位置；显示器坐标与 ScreenCaptureKit 的 `sourceRect` 在首帧校准，不能假设 Retina 缩放恒为 2 倍。
- `ScrollingCaptureService`：用 macOS 13 可用的 `SCStream` 捕获所选显示器的固定 `sourceRect`，通过 `SCContentFilter` 排除 Paster 窗口，每次滚动后只取稳定帧，不把整个录屏持续保存在内存。先确认屏幕捕获权限；流中断、显示器变化或目标应用切换时停止并保留已验证片段。若刚授权后仍无法启动捕获，结束并清理会话，提示重启 Paster 后重试；没有捕获能力时手动模式也不能继续。
- `ScrollDriver`：在选区内部发送少量纵向滚动事件，记录发送前后画面是否移动；事件权限不足或连续无效时允许用户手动滚动。只有用户启动滚动截图后才请求相关系统授权，不复用自动粘贴的开关。
- `ManualScrollDetector`：仅在滚动截图会话期间安装只读 `CGEventTap`，在事件送往目标应用的路径上观察 `scrollWheel`、鼠标按下/拖动和 `keyDown`。`ScrollDriver` 给自己发出的 `CGEvent` 加会话标记；滚动事件未带本次标记、用户在视口内点击/拖动，或目标应用收到用户键盘按键时，都保守地视作接管意图。tap 回调立即把会话的原子状态从 `auto` 改成 `manual`，随后才异步处理画面。`ScrollDriver` 只允许一个自动事件在途；每次发送前检查该状态，不预先排队后续事件。状态切换后，下一次发送必被阻止；若回调与一个已经通过发送检查的事件同时发生，这个在途事件可能仍送达，需真机压测，不能承诺撤回。不读取或记录按键字符，只区分事件类型和必要的键码；tap 不拦截、修改或保存用户事件，停止会话后立即移除。若 tap 创建失败、被系统禁用、缺少观察键盘输入所需授权，或首个本应用标记的滚动事件未被 tap 看到，立即采用手动模式。截图画面在没有本应用滚动的时段发生位移时，也保守地切到手动模式。
- `FrameStitcher`：后台处理相邻帧，估计纵向位移与重叠置信度，识别并只保留一次静止页眉/页脚；只有匹配可靠时才追加像素。会变化的广告、视频、悬浮层或画布可能无法稳定拼接，此时停止并提供可靠的部分结果。通过小幅缩放的图像做匹配，原始分辨率用于输出，及时释放旧帧。
- `PinnedImageManager`：在主线程持有各贴图窗口及原始图片，负责创建、关闭、隐藏/恢复和资源释放。首版最多 10 张、单张最多 2500 万像素、全部贴图合计最多 5000 万像素（按 RGBA 估算约 200 MiB）；滚动结果也受单张上限约束。单张超限提示缩小选区或提前停止，张数或合计像素超限提示关闭贴图，不静默丢弃旧图或载入过大的图片。
- `PinnedImageWindow`：AppKit 的独立无边框窗口，使用浮动级别、阴影和等比缩放；图片与悬停工具栏由视图承载。长图在固定大小窗口内按宽度显示，并提供内部纵向滚动；拖动窗口的手柄与滚动图片的手势分开。窗口关闭时释放图片引用。默认跟随创建时的当前 Space，不主动设置“所有 Space 显示”。
- `ScreenshotCommandController`：接入现有菜单栏和快捷键服务，串联隐藏贴图、两种截图、恢复贴图和创建新窗口；一次只允许一个截图会话。截图进行时不停止剪贴板监听，也不改写现有录制设置。

图片在内存中传递。贴图与滚动截图预览上的“复制”操作将图片写入 `NSPasteboard`；两者都应复用现有的本应用写入标记，防止监听器误把 Paster 的写入当作外部复制。用户在系统截图交互中按住 Control 也可能直接写入剪贴板，这属于系统行为，已启用的历史监听可能记录该结果；需要在帮助文字中提示并真机验证。若 Control 转存的退出状态与剪贴板变化在目标系统上无法可靠识别，统一按“未生成贴图，可重新截图”提示，不读取可能来自其他应用的剪贴板图片。首版不额外把贴图图片写入历史；如果未来要支持“截图自动进历史”，应作为单独设置设计，并严格遵守记录开关、排除应用和保留策略。

## 权限、隐私与失败处理

首次启动 Paster 不请求截屏权限；只有用户主动截图时才进入系统截屏流程。macOS 可能要求“屏幕与系统音频录制”一类授权；自动滚动还可能需要事件发送授权，观察键盘与滚动输入也可能需要辅助功能或输入监控授权。界面需在滚动截图启动时分别说明用途，并在失败时给出系统设置入口。若无法观察用户输入，回退到手动模式，不能在盲目自动滚动的同时让用户操作；若无法捕获画面，则结束会话而不是回退手动模式。首次授予屏幕捕获权限后若本次仍无法启动流，清理当前会话并明确提示重启应用后重试。因为系统命令的授权归属可能随系统版本和打包方式变化，开发阶段必须在干净用户账户、实际 `.app` 和 DMG 安装版上验证；若出现不可解释的归属或重复授权，改用原生 ScreenCaptureKit 实现，不把该问题留给用户。

截图临时目录只允许当前用户访问；成功解码后立即删除临时 PNG。贴图默认不持久化、不上传、不写入日志；错误日志只记录错误类别和状态，不含图片路径或像素。另存为必须由用户明确选择。拒绝授权、命令启动失败、图片损坏和磁盘写入失败均保持现有贴图不变，并给出可操作提示。

## 验收与风险

- 手工验证 macOS 13 及当前开发机系统上的截图成功、`Esc` 取消、拒绝/授予权限；分别覆盖 Retina、外接屏、不同缩放比例和跨屏拖动。先从新构建的 `.app` 重制含此功能的 DMG，再验收该 DMG 的首次安装与截图；现有 v0.1.0 DMG 只是旧版快照，不能用于此项验收。
- 验证多张贴图置顶、移动、等比缩放、关闭、复制、另存为，以及切换 Space、Mission Control、全屏应用和 Stage Manager 时的实际行为；把系统限制写入帮助文字。
- 验证截图前隐藏的旧贴图和历史面板在成功、取消和异常三个分支都按原状态恢复；验证默认 `⌃B` 在快速松键、慢速松键和快捷键冲突时的行为，以及进入系统选区后再次按住 Control 的剪贴板行为。正常退出期间若仍在选区，AppKit 终止流程需延后直到子进程结束与临时文件清理完成；强制退出遗留文件在下次启动清理。原有剪贴板监听、历史搜索和快捷键仍正常。
- 滚动截图用 Safari、Chrome、PDF 阅读器、原生文档视图和至少一种跨平台应用验证自动滚动与拼接。分别在自动滚动发出事件前、等待画面稳定时和连续自动滚动中尝试滚轮、触控板、拖动滚动条、PageDown、空格、方向键及应用自定义键：tap 观察到用户输入后必须立即进入手动模式，不再发送下一次自动滚动；当前输入不得被拦截，手动模式不会自行恢复自动。用密集、交错的人工输入压测接管与发送竞态。tap 不可用、键盘事件不可观察或自动滚动授权被拒时应从开始使用手动模式。验证菜单栏或进度面板的“停止并预览”在目标应用聚焦时可用，并确认所有 Paster 控件都不会混入长图。
- 用固定页眉、动态内容、嵌套滚动区、到达底部、切换窗口/显示器、拼接失败、用户中止和输出像素上限验证可靠部分结果及错误提示；在 macOS 13 与当前开发机上测权限和 ScreenCaptureKit 区域坐标。分别验证屏幕捕获权限被拒、首次授权后捕获仍不可用、事件 tap 授权被拒与运行中被系统禁用的处理。滚动长图贴图必须能在窗口内部继续纵向查看。
- 为截图服务和贴图管理器设计可替换接口，用模拟捕获结果测试状态流转、并发防护、上限和清理；窗口层与系统授权必须在真实 macOS 图形会话中验收。现有命令行自测不能证明真实窗口置顶或授权行为。

## 技术依据

- 本机 `man screencapture`：`-i` 交互选择、`-s` 限制为区域选择、`Esc` 取消、`-t` 指定格式。
- [Apple ScreenCaptureKit 文档](https://developer.apple.com/documentation/screencapturekit)：原生捕获的后续替换方向及权限要求。
- [Apple NSWindow.Level 文档](https://developer.apple.com/documentation/appkit/nswindow/level-swift.property)：浮动窗口位于普通级别窗口之前。
- [Apple NSWindow.CollectionBehavior 文档](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct)：Space、全屏和 Stage Manager 的窗口行为选项。
- [Apple SCStream 文档](https://developer.apple.com/documentation/screencapturekit/scstream)与 [SCStreamConfiguration.sourceRect](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/sourcerect)：滚动截图的连续区域捕获。
- [Apple CGEventTap 文档](https://developer.apple.com/documentation/coregraphics/cgeventtapcreate%28tap:place:options:eventsofinterest:callback:userinfo:%29)、[CGEventSourceUserData](https://developer.apple.com/documentation/coregraphics/cgeventfield/eventsourceuserdata)与 [SCContentFilter 文档](https://developer.apple.com/documentation/screencapturekit/sccontentfilter)：只读观察输入、区分本应用事件及排除 Paster 窗口；事件 tap 权限须真机验证。
